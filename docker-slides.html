The Problem Docker Solves

😤 Without Docker

  • Code works on your MacBook
  • Colleague runs it — it crashes
  • Different Java version
  • Different OS, different libraries
  • "But it works on my machine!"

✅ With Docker

  • Package your app + its environment
  • Same image runs everywhere
  • Developer laptop
  • CI/CD pipeline server
  • Cloud (BTP, AWS, Azure, GCP)

Docker packages your app into a portable box — OS, runtime, dependencies included.

What is Docker?

📄

Dockerfile

A recipe — instructions to build your app's environment step by step

📦

Image

The built package — your app + OS + runtime, frozen and ready to ship

🏃

Container

A running instance of an image — isolated, lightweight, disposable

You write
Dockerfile
→
docker build
creates an Image
→
docker run
starts a Container

VM vs Container

Virtual Machine (VM)Container
What it includesFull OS + hypervisor + appApp + libraries only (shares host OS)
SizeGigabytesMegabytes

IsolationComplete (own OS kernel)Process-level (shared kernel)

Containers are like apartments in a building — separate living spaces, shared foundation.

Our Dockerfile — Stage 1: Build

# Stage 1 — compile the app using Maven + JDK
FROM maven:3.9-eclipse-temurin-17 AS build
# ↑ Start with a machine that already has Maven and JDK 17 installed

WORKDIR /app
# ↑ Create /app folder and work inside it (like: mkdir /app && cd /app)

COPY pom.xml ./
RUN mvn dependency:go-offline -q
# ↑ Copy the dependency list first, download all libraries
#   Docker skips this step next time if pom.xml didn't change (caching)

COPY src ./src
RUN mvn package -DskipTests -q
# ↑ Copy source code, compile it → produces devops-demo-app-1.0.0.jar

At this point: the JAR file exists inside Stage 1. Stage 1 has Maven + JDK (~500 MB).

Our Dockerfile — Stage 2: Runtime

# Stage 2 — fresh start, JRE only, no build tools
FROM eclipse-temurin:17-jre
# ↑ New base image — just the JRE (runs Java, but can't compile it)
#   This is the image that will actually be deployed

WORKDIR /app

COPY --from=build /app/target/devops-demo-app-1.0.0.jar app.jar
# ↑ From Stage 1, take ONLY the JAR. Everything else in Stage 1 is thrown away.

EXPOSE 8080
# ↑ Documents that this app listens on port 8080

ENTRYPOINT ["java", "-jar", "app.jar"]
# ↑ When the container starts, run: java -jar app.jar

Final image: JRE + JAR only (~180 MB). Maven and JDK are gone. Smaller = faster deploys.

Why Two Stages?

Stage 1 — Temporary
  • Maven 3.9
  • JDK 17 (full compiler)
  • Source code
  • Downloaded libraries

Size: ~500 MB

Gets thrown away after build

Stage 2 — Final Image ✓
  • JRE 17 (run only)
  • devops-demo-app.jar

Size: ~180 MB

This is what gets deployed

Analogy: you use a full workshop to build furniture, then deliver only the finished piece — not the entire workshop.

Running Docker — Step by Step

Step 1

Build the image

docker build -t devops-demo-app ./app

Runs the Dockerfile top to bottom. Creates an image named devops-demo-app. Takes ~2 min first time (downloading base images), instant after (cached).

Step 2

Run a container from the image

docker run -p 8080:8080 --name demo-app devops-demo-app

-p 8080:8080 = your laptop's port 8080 → container's port 8080  |  --name = give it a name

Step 3

Test it

curl http://localhost:8080/
# → Hello from SAP DevOps Training!

Useful Docker Commands

CommandWhat it does
docker build -t myapp .Build an image named myapp from Dockerfile in current folder
docker run -p 8080:8080 myappStart a container, map port 8080
docker psList all running containers
docker imagesList all images on your machine
docker stop demo-appStop a running container
docker rm demo-appDelete the container (image stays)
docker logs demo-appView logs from a container

Docker Desktop — What to Look At

📦

Images tab

See devops-demo-app — name, size (~180 MB). This is your packaged app.

🏃

Containers tab

See demo-app running. Click the port link → opens the app in browser.

📋

Logs tab

Click a container → Logs. See Spring Boot startup. First place to check if something breaks.

Key demo: Stop the container → refresh browser → connection refused. Start it again → app is back.
